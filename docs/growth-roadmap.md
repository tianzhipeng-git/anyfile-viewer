# Anyfile 增长行动计划

更新日期：2026-09-29。

目标：获取更多能够完成文件查看任务的访问，并逐步形成回访与外部推荐。本文统一记录首月数据支持的短期行动、持续工作及条件成熟后再启动的能力扩展。除已完成的数据分析和项目现状核查外，下述行动均为待实施计划；候选项不代表已承诺开发。

## 1. 产品边界与执行原则

- 文件在浏览器本地读取、解析与展示，不为预览上传用户文件。
- 只提供查看能力，不提供编辑、转换或云端文件托管。缩放、播放控制、筛选、结构检查和只读比较属于查看范围，不改写源文件。
- 保持轻量、按需加载和有界资源使用；新增功能不能让无关格式承担解码器或首包成本。
- 延续广格式覆盖的方向，仅在有证据的任务上适度深化；不同时扩展成 CAD 编辑器、数据库 IDE、媒体工作站等重型产品。
- 区分三类收益：新增获客、访问后的成功使用、回访。入口优化和预览成功率改善不能直接当作新增流量。
- 每轮只推进一个主要功能实验，基础测量、现有能力验收和配套内容可以同步推进。
- 本文决定投入顺序与验收目标，具体技术方案在实施时结合项目协议和领域文档确定。

## 4. 短期行动

### S1. 建立最小产品测量

2026-09-29 已实现 GA4 接入并从代码移除 Vercel Analytics，保留 Speed Insights。事件口径、首批插件覆盖、后台配置和上线验收见 [产品测量](product-measurement.md)。本地实现与自动测试不代表线上事件已验证；下列验收待发布后的真实浏览器记录确认。

- [ ] 记录任务入口到工作区、选择文件、开始打开、预览成功、失败、取消和兜底的关键节点。
- [ ] 使用明确的成功含义：样例与用户文件分开；视频播放与静态预览分开；Hex 兜底不能自动算作目标任务完成。
- [ ] 仅记录任务入口、格式、插件、大小区间、耗时和可归类的原因；不记录文件名、文件内容、原始错误栈或完整远端文件 URL。
- [ ] 核对分析服务可用的事件能力、来源归因和额度，选取满足本轮判断所需的最小实现。
- [ ] 建立可复查的统计：目标页面访问、选择文件次数、有效打开尝试、目标预览成功与失败原因。

验收：正常、失败、取消、样例及兜底路径各有可核对记录；切换文件不会错误重复计数；能按任务入口查看成功和失败结果。搜索点击与站内事件分别报告，不强行拼成逐用户漏斗。

用途：发现投入在哪一步失效。访问少时检查需求与分发；已到达但不选文件时检查入口和预期；选了文件却打不开时优先修复有代表性的根因。

### S2. 全景素材检查与预览入口

现有能力包括相机系列页、全景环视、部分 INSV 双文件配对、视频播放及特定回退路径。新增重点是让用户清楚知道手中的素材能如何查看。

- [ ] 复用 Insta360、GoPro MAX、DJI Osmo 360 已有页面，保留进入工作区时的相机任务上下文。
- [ ] 提供有分发许可、经过真实验证的小样例，并标明对应格式、素材布局和运行条件。
- [ ] 选择文件后展示已识别的布局、配对是否齐全，以及实际可提供的播放或静态预览能力。
- [ ] 缺配对文件时给明确补选提示；区分不支持的素材布局、编码能力不足与资源/运行环境问题。
- [ ] 对齐机型、格式页和错误提示的支持口径，避免将所有打不开的情况归为文件损坏。
- [ ] 为这条已验证流程准备截图、短演示和操作说明，链接到对应任务入口。

范围：先覆盖已有验证素材，不把这一轮扩大成所有机型支持或通用文件识别工程。INSP 当前验证范围较窄；OSV 的原生 HEVC 要求与 INSV 的回退能力不同，不承诺所有素材都有静态回退。

验收：完整配对、缺配对、已支持布局、不支持布局及解码能力不足都有可理解结果；支持的样例能完成环视或播放；用户可明确区分静态预览与视频播放。桌面流程优先真实验收，同时核对已声明支持的移动场景。

观察：全景任务页的搜索及引荐访问、选择文件、成功预览、失败原因，以及配套演示是否带来真实访问。单纯降低站内操作步骤不算新增获客成果。

### S3. APNG 可控制的动画查看

2026-09-29 已将实现范围扩展为 GIF、APNG、动画 WebP 与 AVIF，复用 `browser-image` 插件，共享按需加载的帧解码与播放模块。使用浏览器 ImageDecoder；不支持对应 MIME 时保留原生预览并提示控制不可用。未引入第三方解码器。

- [x] 实现播放/暂停、上一帧/下一帧、当前帧序号及 0.25×–4× 倍速。
- [x] 展示解码器提供的帧时长、帧数与总播放次数；未知值不猜测。时长标为“解码帧时长”，可能包含浏览器对极短延迟的规范化，并非原始 chunk 字段。
- [x] 提供四种原创渐变样例：通过“打开文件夹”右侧的“样例”按钮以文件夹打开，格式页可下载；补充手机本地文件与控件说明。
- [x] 用户主动控制通过 `animation_control` 记录，与自动播放分开；内置样例显式标记 sample。
- [ ] 完成真实桌面与手机兼容性验收及线上事件确认；详细测试状态见 [动画查看说明](../viewer/plugins/browser-image/ANIMATION.md)。

范围：仅查看，不提供帧导出、编辑或转换。不承诺所有浏览器均有帧控制；原生预览能力也取决于浏览器。可控路径限制输入 128 MiB、单边 8192 像素、单帧 16 Mi 像素、所有帧合计 64 Mi 像素及 10,000 帧，控制解码器内部帧缓存的最坏成本。静态图片保留原路径。

验收：透明混合、处置模式、有限循环、暂停后步进和播放恢复正确；桌面与手机交互可用；切换文件与取消后停止旧动画并释放资源；依赖按需加载。自动测试与真实浏览器验收分别记录，不能将 mock 测试视为真实解码验证。

观察：Bing APNG 查询和入口访问、动画成功打开次数、主动使用控制的次数及具体反馈。样本不足时不将几次零点击解释成标题或排名问题。

### S4. PSB 现有能力验收与错误说明

目前读取已保存的合成图，支持缩放、拖动、旋转及文档元数据。限制为文件 256 MiB、合成图 64 Mi 像素、解码预算 256 MiB；缺少合成图会失败，高位深生成 8-bit 预览。

- [ ] 用真实且可合法使用的 PSB 验收“无需 Photoshop 看合成图”的完整路径。
- [ ] 在选择前明确预览范围和上限，在失败时区分文件超限、像素超限、缺少合成图及其他已确认原因。
- [ ] 按大小区间与原因统计失败，避免通过无依据地提高上限解决问题。
- [ ] 提供可公开体验的合适样例，说明已保存合成图与完整 Photoshop 文档能力的区别。

验收：正常合成图、超限和缺少合成图的结果与声明一致；错误信息具体且准确；没有把高位深预览当作专业色彩输出。

后续候选：如果用户确实需要了解文档结构，可展示已解析的图层名称与分组树。图层数量已存在，名称/分组树尚未实现；本轮不默认新增单层解码或重建图层混合。

## 5. 持续工作

### M1. 扩格式，结合需求研究与本站结果排序

- 保留 `format-demand-research` 的格式需求初筛流程，继续区分市场、语言、意图和数据缺失，不把有效月搜索量当作本站流量预测。
- 新候选先核对插件与真实支持范围，避免把已有能力再次排为新增格式。
- 产品排期另行结合本站搜索表现、打开失败需求、实现/维护成本与验收材料；不改写历史需求评分来适配排期结论。
- 已有 PSB 的本站表现说明，小需求格式也可能先获得入口；同时避免只追踪已经曝光的格式而忽略新市场。
- 每个新增格式明确用户任务、可触达渠道、支持子集与成功标准，不以格式数、页面数作为增长成果。
- 新的付费研究仍按技能流程确定候选和市场，再执行相应授权步骤；本文不预先批准未确定的付费批次。

### M2. SEO 与场景内容

已有静态生成、双语 canonical/hreflang、sitemap、别名重定向和内链基础。持续维护这些能力，不把重复建设基础项当作新增增长计划。

- 每轮分别查看 Google、Bing 的页面和查询表现，优先分析已出现需求的入口；出现抓取或索引异常时再做针对性调查。
- 在现有格式页、相机页补充真实样例、预览效果、任务步骤和支持限制，避免为同一意图新增大量近似页面。
- 改善格式页到工作区的任务连续性。现有“选择文件”按钮实际先导航到 `/view`，方案必须保留 COOP/COEP 所需的完整导航与计算环境边界。
- 相关格式推荐按用户任务和格式关系选择，替代机械取同类别前四项；优先级低于测量和主任务实验。
- 优先完善现有英文与中文入口；没有新增语言需求证据时不批量翻译扩页。
- 根据同一查询/页面及相近条件的趋势判断改动，避免从全站平均排名、小样本 CTR 或短期未收录推导处罚结论。

### M3. 与具体任务绑定的分发

每交付一个可验证场景，准备一份小样例、真实截图、简短演示、支持限制和对应入口，再选择匹配的渠道。

| 渠道 | 行动 | 验证方式 |
| --- | --- | --- |
| 任务教程 | 优先全景素材打开、APNG 查看、无需 Photoshop 看 PSB；包含实际步骤、限制及可体验样例 | 教程搜索与引荐访问是否带来有效预览 |
| 短演示 | 一条演示一个真实任务，先展示选文件到看到结果；中英文材料按目标渠道制作 | 视频带来的访问和实际使用，不只看播放量 |
| 真实求助与社区 | 选择工具确实适用的问题，给完整解决说明，并表明作者身份，遵守社区规则 | 推荐是否帮助完成任务，是否有后续反馈 |
| 垂直网站与创作者 | 围绕摄影/全景、设计素材或具体格式教程提供可测试材料，争取自然引用 | 实际引用来源及有效引荐访问 |
| 软件目录 | 在 AlternativeTo 等适合的目录准确描述产品与限制 | 来源访问及后续使用 |
| GitHub | README 已有英文说明与入口；后续补经验证的演示和任务样例，便于仓库访问者直接体验 | GitHub 引荐和样例到用户文件的使用 |

这些均为待执行的分发计划，不代表已提交目录或联系任何人。准备材料与对外发送/发布分开记录，实际沟通按用户届时明确授权执行；不采用批量无关推广。

## 6. 条件触发的其他能力

### C1. 通用文件识别与兼容性诊断

启动条件：未知文件、后缀错误或兼容性问题形成可观察需求，能够取得有代表性的验证样本。当前搜索数据尚未直接验证通用识别需求。

最小范围：对一小批可靠格式进行有界内容识别，显示实际类型、后缀是否匹配、关键元数据、已确认的预览条件和下一步；识别到支持格式后进入查看器。

实现前提：现有路由先按扩展名筛选，再进行候选 probe，不能通过遍历所有重型插件模拟通用识别。需要正式设计轻量识别层；未知、不支持与已确认异常分别表达，不承诺修复或安全鉴定。

验收与决策：用正确后缀、错误后缀、无后缀及未知内容验证准确性，测量识别后成功预览及即使不能预览仍有用的结果。先从 S2/S4 已验证的局部诊断经验评估是否值得推广。

### C2. 公开 URL、README 按钮与嵌入

启动条件：找到具体的公开文件来源及愿意采用预览入口的仓库、教程或数据集作者。先验证实际分发需求，再扩大集成能力。

1. 先支持少量允许浏览器直接读取的公开来源，完成 URL 到预览；核对 CORS、文件大小及关联资源，不通过代理绕过来源限制。
2. 路径稳定后生成“Open in Anyfile”链接和 Markdown 按钮，让公开文件作者放进自己的内容中。
3. 有实际嵌入需求时，再评估 iframe 或小型 SDK；单独验证跨源隔离、Worker/WASM 和关联文件能力。

边界：分享链接只引用已有公开文件，本地文件不会因生成链接而变成可分享内容；不隐式上传或托管。带认证信息的私有来源不纳入首版，日志与埋点不记录完整文件 URL。

验收与决策：至少完成一条真实来源到预览的流程，并按采用方的引荐访问和成功查看评估。按钮生成数、SDK 安装数或 iframe 展示本身不等于本站访客增长。

### C3. ZIP 内预览与资料包浏览

启动条件：出现收到资料包、需要在内部寻找和连续查看文件的需求。当前工作区已有文件夹和关联资源读取，普通压缩包主要显示目录/元数据；优先补真实缺口。

最小范围：未加密 ZIP 展示目录，点击内部图片、PDF、代码或表格时按需读取条目并复用已有查看器。结合现有 ZIP 条目读取与工作区协议设计，不首先支持全部归档类型或无限嵌套。

验收与决策：多格式资料包可连续只读预览，关联资源路径正确，解压和内存预算有依据，切换时资源释放。用资料交付、设计素材包等具体演示验证入口访问、内部预览成功与复用需求。

### C4. 本地数据检查

启动条件：已有 CSV、Parquet、SQLite、DuckDB 等格式出现重复使用或公开数据分发需求；先选择一个人群和检查任务。

最小范围：字段与样本查看、搜索、筛选、排序，以及有读取预算的类型、缺失值或基础统计。复用已有解析能力，不先做任意 SQL IDE、数据编辑或导出转换。

验收与决策：结果准确，抽样统计与全量统计有清楚区分，大文件处理有明确预算。观察用户是否完成检查、再次使用及推荐；样本不足时不同时深化整个数据领域。

### C5. 双文件比较与批量检视

启动条件：明确出现版本检查或交付物检查需求，先选一种文件类型和比较任务。

候选最小范围：两张图片并排同步缩放、滑杆对照；或两份数据 schema 的只读对照。目录内连续查看可与 C3 结合，但不等于必须新增比较引擎。

验收与决策：用户能定位任务所需差异，不修改源文件。先验证是否比逐个打开省步骤，不直接建设跨所有格式的语义 diff。

### C6. PRN 内容识别与正确路由

启动条件：核对真实文件类型和搜索意图。Bing 的异常小样本不足以支持新打印语言引擎。

当前 PRN 主要支持表格型文本，不能统称任意打印文件查看器。若样本证明有需求，先区分内容；对于明确且已有引擎支持的 PostScript 签名，评估路由到现有页面渲染器。PCL 和任意 spool 不自动纳入范围。

验收与决策：不同内容被准确识别，支持和不支持的结果明确，不把二进制打印数据误呈现为成功打开的表格。

### C7. 留存与便捷入口

启动条件：已有重复使用、离线查看或从其他应用打开文件的明确需求。

候选包括 PWA、有限离线能力、浏览器扩展，以及在实际工作环境中使用的集成入口。先选能减少真实操作步骤的一种，不同时建设多个客户端。在线本地处理不等于已经离线可用，不对尚未缓存的解码器作离线承诺。

验收与决策：衡量重复任务完成和回访，不把安装本身当成新增获客。继续遵守无需桌面软件即可使用主站的定位，桌面端不列为当前建设目标。

## 7. 执行顺序与复盘

| 阶段 | 主要工作 | 进入下一阶段的依据 |
| --- | --- | --- |
| A | S1 测量基线；准备 S2 样例；S4 现有能力验收 | 能区分真实预览结果，主场景有可验收材料 |
| B | S2 全景任务入口与局部诊断；配套 M2/M3 | 流程正确，成功/失败可观察，有可用的演示与入口 |
| C | S3 APNG 控制观看实验；继续观察全景与 PSB | 完成技术验收并收集实际使用，而非只完成页面 |
| D | 复盘并选择深化、调整或一个 C 类候选 | 用新数据或真实需求说明下一项为何值得做 |

每次上线记录日期、变更、目标入口、对照数据范围、真实浏览器验收结果和待观察问题。按周核对已最终确认的数据；以 28 天作为一次完整复盘窗口，不把它当作 SEO 必须见效的期限。此处是执行节奏，不代表已创建定时任务。

继续投入的依据：目标任务有新增有效访问，或能清楚观察到成功使用与真实需求。调整的依据：有访问但预期不符、打开失败集中、来源意图与产品边界不一致。暂缓的依据：缺乏代表性需求、验收材料不足，或成本明显超过目前可验证价值。

当前流量适合观察绝对数量、失败类型和具体反馈，不适合拆成大量 A/B 组，也不设缺乏依据的流量倍增承诺。判断低曝光时，应同时考虑上线时间、索引、排名和市场需求，避免把短期未见增长等同方向无效。
