# 音频查看相关概念

- 状态：规划基线
- 适用范围：浏览器本地打开的独立音频文件，以及 `.mp4`、`.webm`、`.ogg` 等容器中的 audio-only 文件

本文统一本地音频文件查看文档中的术语。分类服务于插件边界、支持等级和验收，不试图建立完整的数字音频百科。

## 1. 产品结果与范围

音频路线图的产品结果是播放主要音频节目，不是只检查标签或展示封面：

- 容器、帧头、轨道和 codec 解析用于选择播放实现、驱动 demux/decode 和解释失败；
- 只展示 metadata、频谱摘要、封面或波形，不算完成一个音频格式；
- 连续播放、暂停、音量、基础 seek、结束、重播和资源释放属于播放底线；
- 用户点击播放前不自动发声；
- 达到播放底线后，优先扩大可播放的容器/裸码流 × codec × sample format 组合；
- 多音轨、cue sheet、章节、歌词、ReplayGain、gapless、封面和 bit-perfect 输出按用户价值后续增强。

以下内容不属于本路线图：

- 视频文件中的主音频；它属于[视频路线图](../videos/roadmap.md)完整播放的一部分；
- HLS、DASH、网络电台、播客订阅等流媒体或远程内容；
- DRM、付费内容和访问控制绕过；
- 麦克风采集、录音、编辑、转码、导出和服务端处理；
- MIDI、工程文件、tracker module、游戏音频 bank 等需要合成器或领域语义的文件；它们可以在未来单独规划。

## 2. 扩展名、容器、裸码流与 codec

### 文件扩展名

扩展名只用于产生候选插件，不能证明文件内容。例如 `.ogg` 可以保存 Vorbis、Opus 或 Theora；`.mp4` 可以是 audio-only，也可以包含视频节目。

### 容器

容器规定轨道、样本、时间轴、索引、标签和 codec 配置如何组织。常见音频容器包括 ISO BMFF/M4A、Ogg、WebM/Matroska、WAVE、AIFF 和 ASF。

### 裸码流或帧流

MP3、ADTS AAC、原生 FLAC 等文件可以由连续音频帧和附加标签构成，而没有通用多轨容器。它们仍需要有界识别、时长/seek 策略和损坏处理，不能只根据同步字节认定整个文件可播放。

### 音频 codec 与 sample format

压缩 codec 包括 AAC、MP3、Opus、Vorbis、FLAC、ALAC、WMA、AC-3 等。PCM 还受采样位深、整数/浮点、符号、端序、打包方式、采样率和声道布局影响。

“支持 WAV”或“支持 AAC”都不是完整声明。支持矩阵至少需要绑定容器或裸码流、codec/profile、sample format、声道和固定样例。

## 3. 音频节目、轨道与辅助图片

### 主音频节目

首期选择一个明确的主音轨并连续播放。存在多个互不等价的主音轨、无法确定默认节目或轨道时间轴不可配对时，不能静默选择并宣称完整支持；可以返回 0，或在未来实现轨道选择后进入声明范围。

### Attached picture / album cover

MP3 APIC、FLAC picture block、MP4 cover art 或容器中的 attached picture 是辅助图片，不是视频节目。音频 probe 可以在有界条件下接受它，视频 probe 不应把它当作主视频轨。

封面不是首期播放门槛。若后续展示，必须限制压缩字节、解码尺寸和像素数，并遵守图片内容安全与资源清理要求。

### 标签、歌词与章节

ID3、Vorbis Comment、APE tag、MP4 metadata、RIFF INFO、cue sheet、章节和歌词不会自动构成支持等级提升。首期只展示有界、可靠、对播放有帮助的信息；不因标签损坏而拒绝仍可安全播放的音频主体，除非标签结构阻止找到音频数据或触发资源边界。

## 4. 时间轴、seek 与 gapless

### 时长

容器索引可以直接提供时长；MP3、ADTS 等可能需要 VBR header、帧索引或受控扫描。不能用文件大小除以首帧 bitrate 冒充准确时长。无法在安全边界内建立基础 seek 时，不进入首批等级 3 声明。

### Seek

Seek 需要从可恢复位置重建 decoder 状态，停止旧 PCM 队列，并防止 seek 前的 buffer 在新 generation 中发声。基础 seek 不要求 sample-accurate，但前后跳转、快速连续 seek、结束和重播必须可验证。

### Gapless 与 encoder delay

编码延迟、padding、edit list 和 gapless metadata 会影响曲目边界。单文件基础播放可以在已声明限制下保持等级 3；宣称 gapless 或专辑连续播放前必须独立验证，不能仅因 decoder 能输出 PCM 就认为已支持。

## 5. 声道、采样率与输出语义

- mono/stereo 是首批基线候选，多声道必须按声道布局和浏览器输出行为单独验证；
- Web Audio 或 `libswresample` 可能重采样、重排或下混，播放可用不等于 bit-perfect；
- 静音是合法内容。`open()` 可以要求取得首个非空、时间戳有效的 decoded buffer，但不能要求样本峰值非零；
- 真实浏览器 smoke 应验证输出链实际调度了 PCM，并使用包含已知非静音区段的固定样例验证可听输出；该证据不能反向用于拒绝合法静音文件。

## 6. 浏览器能力与用户手势

- `<audio>` 的 `canPlayType()` 只能提供可能性判断，不能证明当前文件可解码、可 seek 或全部主轨道可用；
- WebCodecs `AudioDecoder` 不提供通用 demux、播放器状态机或输出设备管理；
- Web Audio 通常要求用户手势后恢复 `AudioContext`，`open()` 不得等待用户点击，也不得自动播放；
- 原生路径以当前文件的真实媒体事件判定打开结果；自定义路径在 `open()` 中完成首个 buffer 解码和可销毁播放链初始化，返回后等待用户播放；
- 支持证据必须记录浏览器完整版本、操作系统、硬件架构和日期。

## 7. 支持等级映射

| 等级 | 音频领域含义 |
|---:|---|
| 0 | 不是目标格式、没有主音频节目、组合不可播放、文件损坏或超出安全边界 |
| 1 | 只能展示标签、容器、帧或轨道结构；不作为音频路线图的交付目标 |
| 2 | 只能展示封面、波形或代表性片段；不作为音频格式支持 |
| 3 | 主要音频节目可连续播放，基础 seek、结束、重播和资源释放可用，但有已声明的高级语义缺失 |
| 4 | 在声明组合内覆盖常见轨道、时间轴、gapless、标签和声道语义 |
| 5 | 在等级 4 上提供该格式所需的领域导航或分析能力 |

音频首批交付以等级 3 为目标，不要求先把已有组合升级到等级 4 才扩展下一种格式。
