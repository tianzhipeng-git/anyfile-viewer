# Anyfile i18n 与多语言 SEO 规范

## 1. 语言范围与发布门禁

共享包 `@anyfile/i18n` 定义十种合法语言：

| 语言 | Locale | 自称 |
|---|---|---|
| 英语 | `en` | English |
| 简体中文 | `zh-CN` | 简体中文 |
| 西班牙语 | `es` | Español |
| 德语 | `de` | Deutsch |
| 法语 | `fr` | Français |
| 日语 | `ja` | 日本語 |
| 葡萄牙语 | `pt` | Português |
| 俄语 | `ru` | Русский |
| 韩语 | `ko` | 한국어 |
| 意大利语 | `it` | Italiano |

默认和最终回退语言是英语。`normalizeLocale()` 负责规范化 BCP 47 输入，无法识别时回退英语。应用层的 `PUBLISHED_LOCALES` 与合法语言分离：首批只发布 `en` 和 `zh-CN`，其余语言不得生成入口、静态参数、sitemap 或可索引页面。

新增发布语言必须同时满足：页面、SEO 元数据、宿主 UI、无障碍文本和所有已注册插件翻译完成；字典契约与插件合规测试通过；人工检查长文案布局后，才可加入 `PUBLISHED_LOCALES`。禁止公开包含英语回退正文的未完成语言页。

## 2. 字典与格式化

- 英语应用字典定义完整键集合；其他发布字典必须键完全一致，不能有缺键、额外键或空字符串。
- 页面字典在 Server Component 中按 locale 动态导入，只把当前页面和客户端组件需要的可序列化数据传入浏览器。
- 变量使用 `interpolate()` 替换；数字、日期和排序使用 `formatNumber()`、`formatDate()` 与 `compareText()`，不得自行拼装地域格式。
- 文件名、扩展名、codec 名称和格式标准名按产品语义保留原文。
- 运行时不得调用外部翻译服务，也不得根据 `navigator.language` 改写已确定的路由语言。

`LocalizedText` 的英语值必填，其他合法语言可选：

```ts
type LocalizedText = Readonly<{
  en: string
} & Partial<Record<Exclude<Locale, "en">, string>>>
```

解析顺序为当前 locale → 英语。应用页面只接收已发布 locale；插件可在开发中收到尚未发布的合法 locale，并按上述规则回退英语。

## 3. 页面路由与 SEO

所有公开页面使用语言前缀：

```text
/{locale}
/{locale}/view
/{locale}/categories/{slug}
/{locale}/formats/{extension}
```

locale 布局只为 `PUBLISHED_LOCALES` 生成静态参数并设置 `dynamicParams = false`。`/`、`/view`、`/categories/:slug`、`/formats/:extension` 使用永久静态重定向迁移到对应 `/en` 地址。根路径不读取 Cookie、Accept-Language 或浏览器语言。

站内链接必须通过 locale-aware helper 保留当前语言。语言选择器仅展示已发布语言的自称，并切换到相同逻辑路径；在 `/view` 切换语言会进行完整文档导航并清空本地文件状态。

每个可索引页面必须生成本地化的 title、description、canonical 和 alternates：

- `hreflang` 只列出已发布语言；
- `x-default` 指向同一逻辑页面的英语 URL；
- sitemap 为两种已发布语言列出 URL，并提供互为 alternate 的关系；
- 非法或未发布 locale 返回 404，不得回退为英语页面。

`catalog` 中的 slug、extension、插件能力等稳定数据只维护一份；显示名称和描述按稳定 ID 本地化，禁止复制格式能力数据。

## 4. 宿主与插件责任

查看器协议 v2 使用统一的 `Locale`：

- `OpenViewerContext.locale` 是 `Locale`；
- `ViewerPluginManifest.name` 与 `SupportedFormat.name` 是 `LocalizedText`；
- 每个注册 Manifest 至少提供非空英语和简体中文名称；
- Manifest 必须保持纯数据，不得导入插件实现、运行时字典、Worker 或 WASM；
- 完整插件选中后才动态加载其实现和用户文案，因此未选插件文案不得进入 `/en/view` 首包。

`ViewerOpenProgress.message` 和用户可见的 `ViewerError.message` 仍是字符串，由插件根据 `context.locale` 生成。按钮、表头、占位符、ARIA、标题、错误、进度和空状态都必须来自当前语言文案。协议校验错误是稳定的英文开发诊断，不作为最终用户文案。

插件不得使用 `startsWith("zh")`、`navigator.language`、临时中英分支或写死单一语言。增加新语言时，每个插件负责补齐自身运行时文案；解析器可保留稳定错误码或内部诊断，但进入用户界面前必须在插件边界完成本地化。

## 5. 隔离、缓存与体积

十种合法的 `/{locale}/view` 都属于跨源隔离页面，以便新增语言后无需修改执行环境判定。已发布的 `/en/view` 和 `/zh-CN/view` 必须返回 COOP/COEP；普通首页、分类页和格式页不返回这些隔离头。

生产 bundle 门禁以 `/en/view` 的预渲染 HTML 为基准，检查首包不包含未选插件实现、probe parser、Worker、WASM 或插件运行时文案。语言页面保持 SSG，以便 CDN 缓存直接按 URL 区分，无需 `Vary: Accept-Language`。

## 6. 验收清单

- 应用字典契约：键集合一致，所有值非空。
- Manifest 合规：协议 v2、唯一 ID、合法格式声明、英语与简中名称完整。
- 插件代表文件分别用 `en`、`zh-CN` 打开，核对主要 UI、进度和错误。
- 验证永久重定向、非法 locale 404、静态参数、canonical、hreflang、`x-default` 与 sitemap。
- 验证两种查看页的 COOP/COEP、普通页面无隔离头，并从真实站内入口确认 `crossOriginIsolated === true`。
- 运行 `pnpm test`、`pnpm lint`、`pnpm build`；不得通过提高 bundle 上限绕过失败。
- 人工检查首页、格式页、工作区及文档、图片、媒体、数据、归档代表插件的布局、语言切换与无障碍名称。
