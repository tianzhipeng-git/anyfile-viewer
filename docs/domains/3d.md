# 3D 与 CAD 查看架构及支持矩阵

本文件记录三维/CAD/点云插件的共享架构边界、当前支持矩阵、安全/依赖审计结论与已知缺口。各插件详细限制与测试命令见对应 `viewer/plugins/*/README.md`。

## 1. 架构边界与共享层

- **`@anyfile/rendering-3d`**：基于锁定 `three@0.185.1`（MIT）WebGL 渲染器与 `OrbitControls`，接收转换后的 `Rendering3dDocument`，接管相机/视图控件、按需绘制、对象显隐、动画播放与 GPU 资源释放，不解析任何文件格式。
- **插件分族**：按领域拆分 `cad-2d`（DXF）、`cad-dwg`（DWG）、`cad-exchange`（STEP/IGES/BREP）、`ifc`（IFC）、`mesh-3d`（STL/OBJ/PLY/OFF/glTF/GLB/FBX/DAE/SKP）、`print-3d`（3MF/AMF）、`point-cloud`（PCD/XYZ/LAS/LAZ）。多格式插件内按格式动态 `import()` 解析器。
- **Worker 与内存**：重型解析运行在独立可终止 Worker，几何缓冲通过 `Transferable` 回传，禁止跨 Worker 传递 `THREE.Object3D`；大坐标统一做原点平移（origin rebasing）避免 Float32 抖动。
- **内容安全**：Three.js loader 与各适配器禁止发起文件内远程 URL 请求；关联资源（MTL、纹理、glTF 外部缓冲）仅通过授权 `WorkspaceReader` 读取，图片纹理仅接受 PNG/JPEG 并受解码像素预算约束。
- **共享 3D 漫游**：非平面文档提供自由漫游与观察点放置（透视相机、WASD/QE、拖动/方向键环顾、滚轮/捏合调 FOV 20°–100°、可见表面拾取、已知单位按米换算眼高与移速、无重力与碰撞、失焦/隐藏/失上下文停绘）。平面文档保持原有视角。

## 2. 当前支持矩阵

| 格式 | 插件 | 等级 | 状态 | 能力范围与主要预算 |
|---|---|---:|---|---|
| ASCII DXF (`.dxf`) | `cad-2d` | 3 | implemented | XYZ 几何、标准视图、orbit、图层显隐；128 MiB / 20 万图元 / 300 万顶点 |
| DWG (`.dwg`) | `cad-dwg` | 3 | implemented | 自建 GNU LibreDWG `0.14-anyfile.1`（GPLv3，源码见 `/source/dwg.html`）；模型空间几何、基础文字/标注/填充；128 MiB / 512 MiB WASM 堆 / 5 MiB C 栈 / 30 s 超时；不含布局/外参/ACIS |
| STEP / IGES / BREP (`.step` `.stp` `.iges` `.igs` `.brep`) | `cad-exchange` | 3 | implemented | 自建 OCCT `0.0.23-anyfile.1`（R2 → 同源）；实体面/边线/名称/颜色/单位；128 MiB 输入 / 256 MiB 堆 / 100 万顶点 / 50 万三角面 / 20 s 初始化超时 |
| IFC (`.ifc`) | `ifc` | 3 | implemented | `web-ifc@0.0.78` 单线程 Worker（jsDelivr → R2 → 同源）；IFC2X3/4/4X3_ADD2 建筑几何、米/Y-up、按类型分组与漫游；128 MiB / 512 MiB 数据内存 / 120 s 超时 |
| STL / OBJ / PLY / OFF / glTF / GLB | `mesh-3d` | 3 | implemented | 网格、材质、本地纹理与 glTF 动画；OBJ 256 MiB / 200 万源顶点 / 300 万展开顶点；共享场景 600 万顶点 / 256 MiB 缓冲 / 4096 绘制；glTF 总纹理 64 Mi 像素 |
| FBX / COLLADA DAE (`.fbx` `.dae`) | `mesh-3d` | 3 | implemented | Worker 内 Three.js 解析（补丁见 `patches/three-worker.md`）+ LinkeDOM 0.18.13；ASCII FBX ≥7000、binary ≥6400；128 MiB / 1200 万标量 / 10 万节点 / 120 s 超时 |
| SketchUp SKP (`.skp`) | `mesh-3d` | 3 | implemented | `openskp@1.3.0` + `patches/openskp@1.3.0.patch`（按定义流式解析 TLV）；128 MiB 输入 / 512 MiB 单条目 / 768 MiB 总展开 / 128 MiB 几何纹理编码 / 60 s 超时 |
| 3MF / AMF (`.3mf` `.amf`) | `print-3d` | 3 | implemented | `zip.js@2.8.60` 有界读取；128 MiB 输入；3MF 2048 条目 / 64 MiB 声明 / 32 MiB 单条目 / 200× 比值；XML 深度 64 / 100 万元素 / 4096 实例 |
| PCD / XYZ / LAS / LAZ | `point-cloud` | 2 | implemented | 有界代表性抽样（20 万点 reservoir）；PCD/XYZ/LAS 上限 2 GiB，LAZ 自建 `laz-perf@0.0.7-anyfile.1` 上限 128 MiB / 256 MiB 堆；不含点属性与完整 LOD |
| USDZ 包 (`.usdz`) | `archive` | 2 | implemented | 仅列出包内条目，无 USD 几何 |

状态变更规则：仅代码存在记 `implemented`，固定样例、反例、资源上限、生命周期测试与真实浏览器 smoke 齐全才记 `verified`；底层库理论支持不代表已支持。

## 3. 安全与依赖审计结论

- **OCCT (`occt-import-js@0.0.23-anyfile.1`)**：拒绝 npm 预编译二进制（默认允许 2 GiB 堆且无输出数量上限），改用源码构建纯 Worker ESM，C++ 层硬限 256 MiB 堆、100 万顶点、50 万三角面、10 万面、4096 mesh/node、深度 64。
  - **残余安全通告**：[CVE-2026-42481 / GHSA-8wqm-37mp-6rrm](https://github.com/advisories/GHSA-8wqm-37mp-6rrm)（中危 5.5，畸形 STEP/IGES B-spline 与循环 `OrientedEdge`，OCCT 7.8.1–8.0.1 尚无确认修复）。当前依赖“每文件一次性可终止 Worker + 128 MiB 输入 / 256 MiB 堆 / 无文件控制网络”缓解，畸形文件仍可能令单个 Worker 失败或卡住直到取消。**提高预算或跨文件复用 Worker 前必须重新审计。**
- **laz-perf (`0.0.7-anyfile.1`)**：源码构建纯 Worker ESM，禁止动态执行，硬限 16–256 MiB WASM 堆（npm 原版默认 2 GiB）。
- **OpenSKP (`1.3.0`)**：通过 `patches/openskp@1.3.0.patch` 避免 F901/7017/7117 组件定义表整棵 TLV 树物化导致 OOM；可用 `SKP_TEST_FILE=/abs/model.skp pnpm test viewer/plugins/mesh-3d` 回归本地大模型。
- **拒绝 `e57-js@1.0.8`**：`Init` 检测 `window` 导致 Worker 走 NODEFS、glue 含动态执行与数 GiB 堆、npm 包缺失 Boost/Xerces/CRCpp 许可声明。若后续支持 E57，必须自建窄化源码 reader。
- **DWG 回归样例**：仓库不分发 DWG 样例，上游来源与哈希见 [dwg-fixture-sources.json](../../tools/libredwg-build/dwg-fixture-sources.json)。

## 4. 待补强与候选方向

- **未实现格式候选**：`3DS`、`USD / USDZ`（需 USD-aware 运行时）、`E57`、`G-code` 刀路。
- **未实现增强能力**：测量、剖切、爆炸图、DWG 图纸空间/UCS/命名视图、glTF Draco/Meshopt/KTX2 扩展、点云完整 LOD 与属性着色。
