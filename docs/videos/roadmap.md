# 视频查看实施路线图

- 状态：规划中，阶段 0 尚未验收
- 范围：浏览器本地打开的视频文件；包含文件内音频和字幕轨道，不包含独立音频文件
- 原则：每阶段交付一个可验证的用户能力，不以创建播放器框架或增加扩展名数量作为完成目标

## 1. 排序方法

视频组合的优先级同时评价：

1. 用户遇到频率和无需转码直接预览的价值；
2. 容器、视频 codec、音频 codec 和 profile 的浏览器原生覆盖；
3. 能否获得可再分发、能够证明编码参数的测试样例；
4. 能否可靠识别轨道与 codec 并进行动态路由；
5. 时长、seek、VFR、rotation、色彩、HDR、多轨和字幕语义；
6. 大文件、畸形索引、解码资源和媒体炸弹风险；
7. 自定义 demux/decode 的维护、体积、许可和部署成本；
8. 能否给出诚实且可复现的支持等级。

## 2. 阶段 0：建立可验收基线

### 工作

- 明确只处理本地视频文件，排除独立音频、流媒体、DRM、编辑和转码；
- 确定需要持续验收的浏览器、操作系统和版本记录方式；
- 建立容器 × 视频 codec × 音频 codec × 关键语义的支持矩阵；
- 确定阶段 1 的首批组合，不用扩展名替代 codec 范围；
- 建立正常、损坏、截断和边界样例清单及再分发依据；
- 定义视频领域的 0–5 级文案；
- 设计 MP4/WebM 的有界 probe 方案，包含文件尾索引、嵌套和轨道数量策略；
- 设计真实浏览器播放、seek、音画同步和清理 smoke test；
- 记录首包、插件 chunk、Object URL 和媒体资源生命周期门禁。

### 首批建议组合

在真实能力 spike 和样例确认前不标记为支持。优先验证：

1. MP4 + AVC/H.264 + AAC；
2. WebM + VP8 + Vorbis 或 Opus；
3. WebM + VP9 + Opus；
4. MP4 video-only 和 WebM video-only，验证无音轨不是错误；
5. audio-only MP4/Ogg/WebM，验证视频 probe 返回 0。

HEVC、AV1、MOV、Ogg Video 不自动进入首批；根据目标环境和样例结果决定阶段 1 或阶段 2。

### 完成标准

- 五份视频规划文档口径一致；
- 每个首批组合至少有一个正常固定样例，并记录精确编码参数和生成/来源方式；
- 每个容器族至少有损坏、截断和伪装扩展名样例；
- 支持矩阵记录目标环境和证据字段，不出现笼统的“支持 MP4”；
- probe 预算和原生媒体资源策略有测量或协议依据；
- catalog 中已有的 MP4/WebM 文案被识别为产品候选，不作为实现证据。

在这些条件满足前，不创建通用媒体框架，也不承诺自定义 codec fallback。

## 3. 阶段 1：浏览器原生视频试点

### 产品能力

- 打开首批经过验证的本地视频组合；
- 使用原生 controls 播放、暂停、音量和基础 seek；
- 不自动播放；
- 显示文件名、可靠的容器/codec 摘要、显示尺寸和时长；
- 保持正确显示比例和浏览器应用后的 rotation；
- video-only 文件正常播放；包含音频的基线文件保持音画同步；
- 文件损坏、codec 不可用和环境不支持时提供准确错误；
- 切换、取消和 dispose 后立即停止播放并释放资源。

### 技术原则

- 新增独立 `browser-video` 插件；
- manifest、probe 和完整实现使用不同入口；
- probe 只进行有界容器/轨道识别并查询辅助能力信号；
- 完整插件使用 `<video controls>` + Object URL；
- 不实现自定义时间轴、解码循环、Canvas 播放或媒体框架；
- `open()` 等待真实文件达到经 spike 选定的首帧可用条件，不能只相信扩展名、MIME 或 `canPlayType()`；
- 没有视频轨道时返回不支持，不截获未来 audio-only 路由；
- 原生路径不设置缺乏依据的统一文件大小、时长或像素上限。

### 完成标准

- 所有声明组合通过协议合规、正常/损坏/截断样例和真实播放 smoke；
- 打开后第一帧可见，基础 seek 可以到开头、中间和接近结尾；
- 含音频样例连续播放并通过可复现的同步验收；
- video-only 样例不会被当成损坏文件；
- audio-only 与伪装扩展名不会被视频插件选中；
- opening abort、active abort、连续切换和重复 dispose 后无声音、回调、Object URL 或媒体加载残留；
- 360×640 窄窗口、900×320 矮窗口和容器 resize 通过手工验证；
- 初始 `/view` bundle 不包含视频完整实现或 probe parser；
- 更新 catalog 和支持矩阵为实际验证结果。

## 4. 阶段 2：容器语义与原生覆盖扩展

阶段 2 不以批量增加扩展名为目标，而是补齐常见真实文件差异。

### 候选范围

- MP4 的 `moov` 在文件尾、fragmented MP4 和常见 edit list；
- 固定帧率、可变帧率和非整数帧率；
- 容器 rotation、pixel aspect ratio 和显示尺寸；
- 多音轨、内嵌文本字幕和章节的实际浏览器暴露情况；
- HEVC、AV1 和 10-bit 组合的目标环境能力；
- MOV 中浏览器可原生播放的明确组合；
- Ogg Video 的真实用户价值和浏览器路径；
- MP4/WebM 中已声明组合的色彩、range 与 HDR 行为。

### 决策原则

- 原生实际播放优先，不因存在新 API 就改写播放管线；
- 多音轨或字幕没有可控、可验证的浏览器路径时，降低支持等级并明确缺失；
- 能播放 SDR 画面不代表 HDR 正确；
- probe 无法在有界预算内精确识别时，保守返回较低等级；
- 只有真实重复出现后才提取 container parser 或媒体 session 公共能力。

### 完成标准

- 每个新增组合有独立样例、环境记录和动态等级；
- seek、rotation、VFR、fragment 和轨道缺失分别有自动或真实浏览器证据；
- 不把系统或硬件依赖能力宣传为跨浏览器统一能力；
- 首包和不相关插件不包含新增 parser 或媒体实现。

## 5. 阶段 3：非原生与专业视频 spike

阶段 3 先验证方案，不预先承诺完整播放器。

### 候选方向

- 浏览器不能原生播放但用户价值明确的 Matroska 组合；
- AVI、MPEG-PS/TS 的代表性组合；
- MOV/MXF 中的 ProRes、DNxHD/HR 和 timecode；
- 只生成封面、关键帧或 contact sheet 的等级 2 预览；
- WebCodecs + 专用 demuxer；
- 经许可、体积和安全评审的 WASM decoder 或 FFmpeg 组件裁剪。

### 进入实现的门槛

- 已有明确、可量化的用户需求，而不是追求格式数量；
- 选定容器和 codec 子集，存在可再分发真实样例；
- demux、视频、音频、A/V clock、seek 和背压方案完整；
- 峰值内存、首帧时间、seek 时间和长期播放稳定性可测量；
- Worker/WASM/GPU 可以取消并完全释放；
- 色彩、HDR、rotation 和音频语义的验收范围明确；
- 依赖版本、许可证、源码/产物、CSP 和部署策略可审计；
- 生产首包与其他插件保持隔离。

### 停止条件

出现以下任一情况时保持 `spike`、`blocked` 或降低等级，不堆叠 workaround：

- 只能解码画面，无法提供可靠音频、同步或 seek，却试图声称完整播放；
- decoder、AudioContext、Worker 或帧缓存不能可靠取消和释放；
- 峰值内存、帧队列或索引大小无法受控；
- 依赖必须运行时从未审计第三方加载，或需要上传用户文件；
- 色彩、HDR、rotation 或时间轴会产生误导结果；
- 没有足够真实样例证明声明范围；
- 许可和专利分发边界无法接受。

## 6. 每个组合的交付清单

- manifest、可选 probe 和完整实现按需分离；
- 扩展名、容器 magic、轨道类型、sample entry 和 codec 配置；
- 动态等级 0–5 的真实文件测试；
- 正常、损坏、截断、伪装和 audio-only 样例；
- duration、首帧、seek、结束、重播和 video-only 行为；
- 含音频文件的音画同步和静音/音量行为；
- rotation、显示比例、VFR、fragment、多轨和字幕的声明范围；
- opening abort、active abort、切换文件和重复 dispose；
- 不修改容器外 DOM，不遗留声音、Object URL、媒体加载、Worker 或 GPU 资源；
- 真实浏览器的窄/矮窗口和 resize 验收；
- 生产 build、首包和插件 chunk 检查；
- 更新支持矩阵、catalog 和用户文案。
